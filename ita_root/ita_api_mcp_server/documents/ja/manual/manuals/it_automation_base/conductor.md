# Conductorの設定と利用方法

Conductorは、Movementを組み合わせた作業フローを定義・実行する機能です。

## メニュー構成

| メニュー | 説明 |
|---|---|
| Conductorインターフェース情報 | インターフェース情報をメンテナンス（閲覧/更新、常に1レコード）。 |
| Conductor通知先定義 | 作業時に実行される通知の定義をメンテナンス（閲覧/登録/更新）。 |
| Conductor一覧 | 登録済みConductorをメンテナンス（閲覧/廃止）。「詳細」でConductor編集/作業実行に遷移。 |
| Conductor編集/作業実行 | Conductorの編集・作業実行を行う。 |
| Conductor作業履歴 | 実行履歴を閲覧。「詳細」でConductor作業確認に遷移。 |
| Conductor作業確認 | 作業の実行結果を確認。 |
| Conductor定期作業実行 | スケジュールに従い定期実行するConductor作業をメンテナンス（閲覧/登録/更新）。 |

## 標準的な作業フロー

1. 機器情報を登録・確認（Ansible共通）。
2. オペレーションを登録・確認（基本コンソール）。
3. 各DriverからMovementを登録し、確認（基本コンソール）。
4. Conductorインターフェース情報を登録。
5. Conductorを登録・確認。
6. Conductorを実行し、結果・履歴を確認。

Conductor実行時、各Movementで共有するディレクトリパス（Ansible driver対象）を利用することでMovement間の情報伝達が可能です。「Conductor call」で呼び出した作業フローはそれぞれ個別の共有ディレクトリを持ち、作業フローを跨いだMovement間では共有できません。

## Conductorインターフェース情報

各Movementで共有するディレクトリパスと「Conductor作業確認」のリフレッシュ間隔を設定します。項目: ConductorインターフェースID（自動採番）、状態監視周期（単位ミリ秒、必須、最小1000ミリ秒、推奨1000ミリ秒程度）、備考。

## Conductor通知先定義

作業時に実行される通知の定義を設定します。

| 項目 | 説明 | 必須 |
|---|---|---|
| Conductor通知ID | 自動採番 | - |
| 通知名称 | 任意の名称 | 〇 |
| 通知先URL | 通知先のURL | 〇 |
| ヘッダー | HTTPヘッダフィールド（JSON形式） | 〇 |
| メッセージ | 通知先サービス仕様に沿った内容（ITA独自変数を使用可、後述） | 〇 |
| PROXY URL／PORT | プロキシが必要な場合に指定 | 〇 |
| 作業確認URL | 作業確認URLの予約変数で使うFQDN | 〇 |
| 抑止開始日時／終了日時 | 通知を抑止したい期間 | 〇 |
| 備考 | 自由記述 | - |

メッセージで使えるITA独自変数: `__CONDUCTOR_INSTANCE_ID__`（ConductorインスタンスID）、`__CONDUCTOR_NAME__`（Conductor名称）、`__STATUS_ID__`（ステータスID）、`__OPERATION_ID__`/`__OPERATION_NAME__`（オペレーション）、`__EXECUTION_USER__`（実行ユーザー）、`__PARENT_CONDUCTOR_INSTANCE_ID__`/`__PARENT_CONDUCTOR_NAME__`（親Conductor）、`__TOP_CONDUCTOR_INSTANCE_ID__`/`__TOP_CONDUCTOR_NAME__`（最上位Conductor）、`__ABORT_EXECUTE_FLAG__`（緊急停止フラグ）、`__REGISTER_TIME__`/`__TIME_BOOK__`/`__TIME_START__`/`__TIME_END__`（登録/予約/開始/終了日時）、`__NOTICE_NAME__`（通知ログ）、`__NOTE__`（備考）、`__JUMP_URL__`（作業確認画面URL、作業確認URLを使用）。

ステータスID対応表: 3=実行中、4=実行中（遅延）、5=一時停止、6=正常終了、7=異常終了、8=警告終了、9=緊急停止、10=予約取消、11=想定外エラー。

作業確認URLの出力例（作業確認URL(FQDN)が`http://localhost:38000`の場合）: `http://localhost:38000/org002/workspaces/workspace1/ita/?menu=conductor_confirmation&conductor_instance_id=X`

### 通知先定義の設定例

**Teams例**: ヘッダー`["Content-Type: application/json"]`、メッセージ`{"text": "通知名：__NOTICE_NAME__, Conductor名称: __CONDUCTOR_NAME__, ConductorインスタンスID:__CONDUCTOR_INSTANCE_ID__, ステータスID: __STATUS_ID__, 作業URL: __JUMP_URL__"}`

**Slack例**: 通知先にSlack Webhook URLを指定し、他はTeamsと同様の構成。

**Proxy・通知抑止・その他設定を含む例**: 通知先URL、ヘッダー、メッセージに加え、PROXY URL/PORT、作業確認URL、その他（`{"CURLOPT_TIMEOUT":"10"}`のようなcURLオプション）、抑止の開始日時・終了日時を設定可能。

### 通知ログの構造

```json
[
  {
    "conductor_status_id": "3",
    "exec_time": "2023/07/05 16:29:50",
    "result": [
      {
        "notice_name": "test",
        "notice_info": ["3","4","5"],
        "status_code": 200,
        "response.headers": {},
        "response.text": "1"
      }
    ]
  }
]
```

異常時は`status_code`がエラーコード（例: 400）、`response.text`にエラー内容、`err_type`（例: `HTTPError`）が追加されます。

## Conductor編集/作業実行

### モード

| モード | 説明 |
|---|---|
| 編集 | 新規Conductor作成（デフォルトモード）。「選択」で既存Conductorを選ぶと閲覧モードに変わる。 |
| 閲覧 | Conductorの閲覧のみ（Conductor一覧の「詳細」から遷移）。「編集」で更新モードに変わる。 |
| 更新 | 既存Conductorの編集（「更新」で閲覧モードに戻る）。 |

### Node（作業フローのパーツ）

| Node | 動作 |
|---|---|
| Conductor start | Conductorを開始する。 |
| Conductor end | Conductorを終了する（複数ある場合、全Conductor endの終了を待つ）。終了ステータスを「正常」（デフォルト）「警告」「異常」から選択、複数End通過時は優先度「正常＜警告＜異常」の高い方が反映される。 |
| Conductor pause | 作業フローを一時停止（解除すると次処理へ進む）。 |
| Conductor call | 別の登録済みConductorを呼び出し実行（呼び出し先が警告終了で終わっても正常終了と同様に扱われ、呼び出し元ステータスに影響しない）。個別オペレーションを指定可能。 |
| Conditional branch | 接続されたMovement/Conductor callの結果で後続処理を分岐（分岐可能なステータス: 正常終了/異常終了/緊急停止/準備エラー/想定外エラー/SKIP完了/警告終了、最大6 case）。デフォルトはcase1=正常終了、Other=それ以外。 |
| Parallel branch | Movement/Conductor callを並列実行（並列数はITA構成・サーバースペックに依存、デフォルト分岐数2、2未満不可）。 |
| Parallel merge | 接続した全Nodeの処理完了後に次処理を実行（デフォルト分岐数2、2未満不可）。 |
| Status file branch | Movementの作業結果ディレクトリ内のステータスファイル内容で分岐（デフォルトはif/else、条件追加・削除可）。 |
| Movement各種 | Movementを実行する。 |

**Node制約事項**: 全NodeのIN/OUTが接続されている必要がある。Parallel mergeはParallel branchと対で使用する必要がある（Conditional branchで分岐したフローをParallel mergeでマージすることは不可）。Parallel branch・Conditional branch・Parallel merge・Conductor pauseは同種のNodeを連続接続できない。更新中のConductorをConductor callで指定して更新することはできない。

**Status file branchの参照先**: 各Movementの作業結果ディレクトリ配下の`MOVEMENT_STATUS_FILE`（ITA独自変数`__movement_status_filepath__`で参照可能）。ファイルが存在しない場合は「else」側の処理を実施。内容が複数行の場合、最初の改行より前の値のみを評価対象とする。

### Node詳細情報タブ（編集/更新モード）

- **Conductorタブ（Node未選択時）**: ID（自動）、名称（必須）、更新日時（自動）、通知（ステータス毎に複数選択可、Conductor通知先定義で登録したもの）、Movement共通表示設定（ノード幅・Movement名表示形式）、備考。
- **Movement選択時**: Movement ID・名称（自動表示）、スキップ（作業実行画面でも変更可能）、個別オペレーション（選択したオペレーションで実行することが可能。「代入値管理」の別オペレーションIDに登録した具体値を使う用途）、備考。
- **Conductor call選択時**: スキップ、呼び出しConductor、個別オペレーション。
- **Conditional branch選択時**: 条件分岐設定（分岐追加/削除、最大6件）。
- **Parallel branch選択時**: 平行分岐設定（分岐追加/削除、デフォルト2、下限2）。
- **Parallel merge選択時**: case設定（マージ追加/削除、デフォルト2、下限2）。
- **Conductor end選択時**: 終了ステータス（正常/警告/異常）。
- **Status file branch選択時**: ステータスファイル分岐設定、備考。
- **複数Node選択時（Nodeタブ）**: 左揃え/左右中央揃え/右揃え/上揃え/上下中央揃え/下揃え/左右等間隔/上下等間隔の整列操作。

閲覧モードの操作: 選択（既存Conductorを選んで閲覧）、編集、作業実行、流用新規（コピーして新規作成）、新規。更新モードの操作: 更新、再読み込み（変更破棄）、キャンセル（編集前に戻る）、フルスクリーン、全体表示（全Node表示縮尺）。

### Conductor作業実行

閲覧モードで「作業実行」をクリックすると作業実行設定画面が表示されます。

| 項目 | 説明 | 必須 |
|---|---|---|
| 作業実行 Conductor | 選択したConductor（自動表示） | - |
| オペレーション | 基本コンソールのオペレーション一覧から選択 | 〇 |
| スケジュール | 実行予定日時（現在時刻より過去は入力不可） | - |
| 作業実行 | 実行ボタン | 〇 |

実行時にMovement/Conductor callのオペレーション・スキップのみ個別に変更可能ですが、この変更はConductor編集の登録データには反映されず、実行時のみに適用されます（**編集/更新モードでの個別指定は登録・更新で保存され、作業実行画面での個別指定は実行時のみ有効で保存されない**という違いがあります）。予約日時を指定して実行すると作業予約となり、Conductor作業履歴で確認できます。実行時に選択したConductorとオペレーションに設定されたアクセス権の共通ロールを継承し、共通ロールがない場合は実行できません。

## Conductor作業履歴

実行済みConductor作業を管理します。フィルタで作業履歴を検索し、「詳細」でConductor作業確認へ遷移します。「投入データ一式(zip)」「結果データ一式(zip)」で、実行された全Conductor配下のMovement（階層構造の場合は末端のMovementも含む）の実行ファイル・ログをまとめてダウンロードできます。

## Conductor作業確認

Conductorの実行状態を表示します。実行中以降のステータスの実行状況サークルをクリックすると各ドライバの「作業状態確認」に遷移できます。処理状況をモニターし、状況に応じて「予約取消」「停止解除」「緊急停止」を投入できます。

**注意**: 作業実行済みのConductorをConductor編集/作業実行で編集すると、実行時と異なる状態になるため「詳細」で処理状況が表示されない場合があります。実行済みConductorを編集して再実行する場合は「流用新規」で別Conductorを作成することが推奨されます。

**Conductorタブ**（Node未選択時）: Conductorインスタンス情報（ID、名称、ステータス：未実行/未実行（予約）/実行中/実行中（遅延）/一時停止/正常終了/異常終了/警告終了/緊急停止/予約取消/想定外エラー、開始/終了時間、実行ユーザ、予約日時、緊急停止有無）、オペレーション、備考。

**Nodeタブ**（Node選択時）: Nodeインスタンス情報（ID、種別、Node ID（JSON構成上のID）、ステータス：未実行/準備中/実行中/実行中（遅延）/正常終了/異常終了/想定外エラー/緊急停止/一時停止/準備エラー/Skip終了/警告終了、Stファイル（Movementの場合のStatus file値）、開始/終了日時）、個別オペレーション、備考。

## Conductor定期作業実行

スケジュールに従い定期的に実行するConductor作業を管理します。「作業履歴」ボタンでその定期作業の実行対象をフィルタしたConductor作業履歴に遷移できます。

| 項目 | 説明 | 必須 |
|---|---|---|
| 定期作業実行ID | 自動採番 | - |
| Conductor名称 | Conductor一覧から選択 | 〇 |
| オペレーション名 | オペレーション一覧から選択 | 〇 |
| ステータス | 下表参照（自動） | - |
| 実行ユーザ | 登録・更新実行ユーザが引き継がれ、定期実行登録時のConductor実行ユーザになる | - |
| スケジュール設定：開始日付 | 定期実行の開始日付（次回実行日付はこれ以降で更新される） | 〇 |
| スケジュール設定：終了日付 | 定期実行の終了日付（次回実行日付がこれを超えるとステータス「完了」） | - |
| スケジュール設定：周期 | 「時」「日」「週」「月(日付指定)」「月(曜日指定)」「月末」 | 〇 |
| スケジュール設定：間隔 | 周期に基づく実行間隔 | 〇 |
| スケジュール設定：週番号／曜日 | 周期が「月(曜日指定)」の場合必須（曜日は「曜日」周期でも必須） | 条件付き |
| スケジュール設定：日 | 周期が「月(日付指定)」の場合必須 | 条件付き |
| スケジュール設定：時間 | 周期が「日」「週」「月(日付指定)」「月(曜日指定)」「月末」の場合必須 | 条件付き |
| 作業停止期間：開始／終了 | 設定する場合両方必須。この期間中はConductor作業登録が行われない | 条件付き |
| 備考 | 自由記述 | - |

### ステータス一覧

| ステータス | 説明 |
|---|---|
| 準備中 | 登録直後の状態。backyardが次回実行日付を更新すると「稼働中」になる。 |
| 稼働中 | 正常稼働中。次回実行日付より「Conductorインターバル時間設定」の時間前にConductor一覧へ作業登録し、次回実行日付を再更新する。 |
| 完了 | 次回実行日付が終了日付を超えた状態。以降作業登録しない。 |
| 不整合エラー | スケジュール設定値が不正な場合。 |
| 紐付けエラー | Conductor一覧への作業登録が失敗した場合。稼働中と同様に登録・更新を継続するが、再度失敗するとこの状態が継続する。 |
| 想定外エラー | 不整合エラー・紐付けエラー以外の不具合が発生した場合。 |
| Conductor廃止／operation廃止 | 対象Conductor／operationが廃止された場合（復活させると「準備中」に戻る）。 |

「Conductorインターバル時間設定」は管理コンソールのシステム設定から、次回実行日付の何分前に作業登録を実行するか設定できます。

**注意**: メニューエクスポート・インポートで異なるオーガナイゼーション間を移行した際、実行ユーザがID変換失敗になる場合があり、その状態で定期作業実行するとステータスが「紐付けエラー」になります。この場合、レコードを更新して実行ユーザをID変換失敗でない状態にする必要があります。

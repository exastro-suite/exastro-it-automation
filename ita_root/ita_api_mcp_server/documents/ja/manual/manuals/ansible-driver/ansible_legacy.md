# Ansible-Legacyの設定と利用方法

Ansible-Legacyは、Ansible標準機能で各種ホストへ設定を投入するモードです。構築コードを単体YAMLファイル（Playbook）として登録し、作業パターンをその組み合わせで構成します。サーバ・ストレージ・ネットワーク各機器の環境設定作業向けです。

## メニュー構成

基本コンソール（オペレーション一覧）とAnsible共通のメニューに加え、Ansible-Legacy独自のメニュー: Movement一覧（Movementの管理）、Playbook素材集（Playbookファイルの管理）、Movement-Playbook紐付（MovementでインクルードするPlaybookの管理）、代入値自動登録設定（パラメータシート項目とMovement変数の紐付管理）、作業実行、作業管理（履歴管理）、作業状態確認、作業対象ホスト（作業実行毎の対象ホスト表示）、代入値管理（作業実行毎の変数具体値表示）、Movement-変数紐付（非表示メニュー、内部処理用）。

## 作業フロー

1. Ansible共通の機器一覧に接続情報を登録。
2. 基本コンソールのオペレーション一覧にオペレーション名を登録。
3. 必要に応じてAAPホスト情報・インターフェース情報（実行エンジン選択と接続情報）を登録。
4. 必要に応じて実行環境定義テンプレート管理・パラメータシート「実行環境パラメータ定義」・実行環境管理を登録。
5. Movementを登録し、Playbookを登録。
6. 必要に応じてグローバル変数・テンプレートファイル・ファイル素材・管理対象外変数を登録。
7. MovementにPlaybookを紐付ける（Movement-Playbook紐付）。
8. パラメータシートを作成しデータを登録。
9. 代入値自動登録設定でパラメータシート項目とMovementの変数を紐付ける。
10. 作業実行 → 作業状態確認（リアルタイム監視、緊急停止、ログ確認）→ 作業管理（履歴確認）。

## Movement一覧

Movement情報をメンテナンス（閲覧/登録/更新/廃止）します。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| MovementID | 自動採番（36桁） | - |
| Movement名 | 任意の名称 | 必須、最大255バイト |
| 遅延タイマー | 指定期間（1分〜）遅延時に作業状態確認のステータスを「実行中（遅延）」として警告表示。未入力なら警告なし | 0〜2147483647 |
| Ansible利用情報：ホスト指定形式 | IPアドレスで表現しないホストを指定する場合「ホスト名」を選択 | 必須 |
| Ansible利用情報：WinRM接続 | 対象がWindowsServerの場合True（選択すると全対象ホストをWindowsServerとみなす） | - |
| Ansible利用情報：ヘッダーセクション | 自動生成される親Playbookの先頭〜tasksセクション手前を編集。未入力時は下記デフォルトを適用。変数記述可（例: `become_user: '{{△vvv△}}'`）、具体値は代入値自動登録設定から登録 | 最大4000バイト |
| Ansible利用情報：オプションパラメータ | Movement固有のオプション。実行エンジンがCore/Agentならansible-playbookオプション、AACならジョブテンプレートパラメータ | 最大4000バイト |
| Ansible利用情報：ansible.cfg | 作業実行時使用のansible.cfgファイル（未アップロード時デフォルト使用） | 最大100MB |
| Ansible Execution Agent利用情報：実行環境 | 実行環境管理に登録済みの実行環境名。実行エンジンがAgentの場合必須 | - |
| Ansible Execution Agent利用情報：ansible-builderパラメータ | ansible-builderで実行環境buildする際のパラメータ | 最大4000バイト |
| Ansible Automation Controller利用情報：実行環境 | AACに構築されている実行環境（AAC同期データから選択）。未選択時はAACのデフォルト実行環境 | - |
| 備考 | 自由記述 | 最大4000バイト |

ヘッダーセクションのデフォルト:
```yaml
- hosts: all
  remote_user: "{{ __loginuser__ }}"
  gather_facts: no
  become: yes
  # winrm接続の場合は become: yesは適用しません。
```
`become: yes`を設定する場合、対象ホストのログインユーザのsudo権限をNOPASSWD付きで`/etc/sudoers`に設定する必要があります（例: `Demo_user ALL=(ALL) NOPASSWD:ALL`）。

## Playbook素材集

ユーザ作成のPlaybookをメンテナンス（閲覧/登録/更新/廃止）します。初期状態でサンプルPlaybook（素材名先頭に「~[Exastro standard]」）が登録されており、Movementと紐付けて利用できます。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| プレイブック素材名 | 任意の名称 | 必須、最大255バイト |
| プレイブック素材 | Playbookファイル（UTF-8 BOMなし） | 必須、最大100MB |
| ターゲット：Linux/Windows | 使用可能OSに「＊」を選択（未選択でも実行に影響なし） | - |
| ターゲット：その他 | Linux/Windows以外の用途を入力 | 最大4000バイト |
| Python要否 | 対象機器にPythonが必要なら「＊」（未選択でも実行に影響なし） | - |
| 説明／説明(en)／備考 | 自由記述 | 各最大4000バイト |

内部処理でのPlaybook内変数の抽出はリアルタイムでないため、代入値自動登録設定で変数が扱えるまで時間がかかる場合があります。

## Movement-Playbook紐付

MovementでインクルードするPlaybookをメンテナンス（閲覧/登録/更新/廃止）します。項目: Movement（リスト選択、必須）、Playbook素材（リスト選択、必須）、インクルード順序（1〜2147483647、昇順で実行、必須）、備考（最大4000バイト）。

## 代入値自動登録設定

パラメータシート項目の設定値とMovementの変数の紐付を管理（閲覧/登録/更新/廃止）します。登録情報は作業実行時に「代入値管理」「作業対象ホスト」に反映されます。

| 項目 | 説明 | 必須 |
|---|---|---|
| パラメータシート(From) メニュー:項目 | パラメータシート（ホスト/オペレーションあり）の項目 | 〇 |
| パラメータシート(From) 代入順序 | バンドル使用時、パラメータシートの代入順序を入力 | バンドル使用時のみ必須 |
| 登録方式 | Value型（項目の設定値が具体値になる）／Key型（項目の名称が具体値になる） | 〇 |
| Movement名 | 登録したMovement | 〇 |
| IaC変数(To) Movement名:変数名 | Movement-Playbook紐付の資材で使用している変数 | 〇 |
| IaC変数(To) 代入順序 | 複数具体値変数にする場合の代入順序（1〜）。具体値が1個でも入力が必要 | 複数具体値変数の場合必須 |
| NULL連携 | True（どのような値でも登録）／False（値が入力されていれば登録）。未選択時はインターフェース情報の値を適用 | - |
| 備考 | 自由記述 | 最大4000バイト |

パラメータシート（バンドル）を使う場合のみ、パラメータシート(From)の代入順序が必須です。代入順序が未入力の変数は通常変数、入力されていれば複数具体値変数として扱われます（代入順序が連続していなくても詰めて処理される）。代入値自動登録設定で登録した変数のみが作業実行時にホスト変数ファイルへ出力されます（Playbookで使用中でも未登録の変数は出力されず、ansible実行時に変数未定義エラーとなる場合がある）。

**複数具体値変数の例**: パラメータシートの項目1〜4にvalue1〜4を登録し、代入値自動登録設定で`VAR_substitutionA`に項目1=30, 項目2=10, 項目3=20の順序を、`VAR_substitutionB`に項目1=2, 項目2=4, 項目3=1, 項目4=3の順序を設定すると、ホスト変数ファイルには`VAR_substitutionA: [value2, value3, value1]`、`VAR_substitutionB: [value3, value1, value4, value2]`のように昇順で出力されます。

**ファイル埋込変数・テンプレート埋込変数の利用例**: ファイル管理に`CPF_test`（ファイル素材`test_file.txt`）、テンプレート管理に`TPF_sample`（テンプレート素材`sample.tpl`）を登録し、パラメータシートの項目値としてこれらの埋込変数名を設定、代入値自動登録設定でPlaybookの変数（例: `VAR_filetest`, `VAR_temptest`）に紐付けることで、作業実行時に代入値管理上の具体値が`'{{ CPF_test }}'` `'{{ TPF_sample }}'`として反映されます。

## 作業実行

Movementとオペレーションを選択し、実行種別を指定して実行します。実行結果は作業状態確認で確認できます。

- **作業実行**: 対象に構築作業を実行。
- **ドライラン**: 実際には変更せず、ansible-playbookの`--check`相当を実行。
- **パラメータ確認**: 構築作業をせず、代入値自動登録設定の情報を「代入値管理」「作業対象ホスト」に反映して確認できる。
- **予約日時**: 未来日時のみ指定可能で、実行を予約できる。

## 作業状態確認

作業の実行状態を監視します。「実行種別」は通常/ドライラン/パラメータ確認。想定外エラー時はエラーログにメッセージが表示されます。「呼出元Conductor」はConductor実行時のみ設定。

AACで実行した場合、機器一覧のユーザ・パスワード・ssh秘密鍵ファイル・パスフレーズ・接続タイプ・インスタンスグループの値でグループ化された単位でPlaybookが実行され、ログも分割されます。さらにインターフェース情報またはMovement一覧のオプションパラメータでジョブスライス数を指定すると、グループ内がさらに分割されます。実行ログはTab表示され、`exec.log`（全ログ）と`exec_<グループ番号>_<通番>`（分割ログ、通番0は未分割）があります。

その他の機能: 作業対象ホスト確認・代入値確認ボタン、緊急停止／予約取消ボタン、ログ検索（文字列検索・該当行のみ表示、リフレッシュ間隔/最大行数はインターフェース情報の設定に従う）、投入データ・結果データのダウンロード、収集状況（ステータス: 収集済み／収集済み（通知あり）／対象外／収集エラー）。

## 作業管理 / 作業対象ホスト / 代入値管理

**作業管理**: 作業履歴を一覧・フィルタ表示。項目: 作業No.、実行種別、ステータス、緊急停止フラグ、実行エンジン、呼出元Conductor、実行ユーザ、登録日時、Movement（ID/名称/遅延タイマー/Ansible利用情報各種/Ansible Execution Agent利用情報/AAC利用情報）、オペレーション（No./名称）、投入データ・結果データ、作業状況（予約/開始/終了日時）、収集状況、Conductorインスタンス番号。

**作業対象ホスト**: 作業実行毎の対象ホストを閲覧（項番、作業No、オペレーション、Movement名、ホスト名、備考）。

**代入値管理**: 作業実行毎の変数具体値を閲覧。項目: 項番、作業No、オペレーション、Movement名、ホスト名、Movement名:変数名、具体値（Sensitive設定True時は暗号化されansible-vault経由、False時は具体値を表示／ファイル名）、代入順序、備考。

## Playbook（Ansible-Legacy）の記述

アップロードされたPlaybookは、ITAが生成するマスターPlaybookからinclude形式で実行されます。マスターPlaybookはヘッダーセクションとtasksセクションで構成され、アップロードするPlaybookにヘッダーセクションは不要です（Movement一覧のヘッダーセクションで変更可能、デフォルトは前述の通り）。tasksセクションはAnsible公式のPlaybook書式に従い記述し、Movement-Playbook紐付のインクルード順序に従ってincludeされます。

## 付録: Ansible実行時の投入データとITAメニューの紐づけ

ITAの各メニュー情報から投入データを生成します（機器一覧のパスワードやSensitive設定Trueの変数具体値はansible-vaultで暗号化）。投入データはZIP形式で作業状態確認からダウンロードでき、解凍してAnsibleを直接実行することも可能です。主な対応関係: Playbook素材→`/child_playbooks`、テンプレート素材→`/template_files`、ファイル素材→`/copy_files`、代入値管理の具体値（ファイル）→`/upload_files`、グローバル変数・代入値管理・テンプレート/ファイル埋込変数・機器一覧の各情報→`/host_vars`、ssh認証鍵ファイル→`/ssh_key_files`、winrm鍵ファイル→`/winrm_key_files`、サーバ証明書→`/winrm_ca_files`、オプションパラメータ→`/AnsibleExecOption.txt`（Core/AAC）または`/env/cmdline`（Agent）、機器一覧の接続情報→`/hosts`（Core/AAC）または`/inventory/hosts`（Agent）、Playbook名・インクルード順序→`/playbook.yml`、実行環境関連ファイル（Agent利用時のみ）→`builder_executable_files/`、`runner_executable_files/`。

## 付録: Ansible実行時の結果データ

実行結果はZIP形式で保存され、作業状態確認からダウンロード可能です。主なファイル: `result.txt`（Ansible実行結果、Core限定）、`error.log`（エラー出力、全エンジン共通）、`exec.log.org`/`exec.log`（標準出力/加工済みログ、全エンジン共通）、`exec_<作業番号>_<グループ番号>`（分割ログ、AAC限定）、`forced.txt`（緊急停止記録、Core/Agent）、`user_files`（`__workflowdir__`への出力先、全エンジン共通）、`child_exec.log`/`child_error.log`（ansible-builder実行ログ、Agent限定）。

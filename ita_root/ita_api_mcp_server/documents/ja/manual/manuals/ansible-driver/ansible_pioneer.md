# Ansible-Pioneerの設定と対話ファイルの記述方法

Ansible-Pioneerは、Ansibleに独自モジュールを追加し、対話形式で設定投入するモードです。Telnet/SSHでログイン可能なサーバ・ストレージ・ネットワーク機器に対応します。

## メニュー構成

基本コンソール・Ansible共通のメニューに加え、Ansible-Pioneer独自メニュー: Movement一覧、対話種別（同一目的の対話ファイルをまとめる分類の管理）、OS種別（作業対象機器のOS種別管理）、対話ファイル素材集（対話種別×OS種別ごとの対話ファイル管理）、Movement-対話種別紐付（Movementでインクルードする対話種別の管理）、代入値自動登録設定、作業実行、作業管理、作業状態確認、作業対象ホスト、代入値管理、Movement-変数紐付（非表示メニュー、内部処理用）。

## 作業フロー

1. OS種別を登録し、機器一覧に接続情報、オペレーション一覧にオペレーション名を登録。
2. 必要に応じてAAPホスト情報・インターフェース情報・実行環境関連を登録。
3. Movementを登録し、対話種別を登録。
4. 対話種別とOS種別の組み合わせに対して対話ファイルを登録（対話ファイル素材集）。
5. 必要に応じてグローバル変数・テンプレート・ファイル素材・管理対象外変数を登録。
6. Movement-対話種別紐付でMovementに対話種別を紐付ける。
7. パラメータシートを作成・データ登録し、代入値自動登録設定でMovementの変数と紐付ける。
8. 作業実行 → 作業状態確認 → 作業管理で履歴確認。

## OS種別

作業対象機器のOS種別をメンテナンス（閲覧/登録/更新/廃止）します。項目: OS種別名（必須、最大255バイト）、機器種別（SV/NW/ST、それぞれTrue/False選択）、備考。

## Movement一覧

| 項目 | 説明 | 制約事項 |
|---|---|---|
| MovementID | 自動採番 | - |
| Movement名 | 任意の名称 | 必須、最大255バイト |
| 遅延タイマー | 指定期間（1分〜）遅延時に警告表示。未入力なら警告なし | 0〜2147483647 |
| Ansible利用情報：ホスト指定形式 | IPアドレスで表現しないホスト指定時に「ホスト名」を選択 | 必須 |
| Ansible利用情報：ansible.cfg | 作業実行時使用のファイル（未アップロード時デフォルト） | 最大100MB |
| Ansible利用情報：並列実行数 | ansible-playbookの`--forks`相当の値 | 1〜4294967296 |
| Ansible Execution Agent利用情報：実行環境／ansible-builderパラメータ | Agent利用時は実行環境が必須 | 実行環境は最大4000バイト |
| Ansible Automation Controller利用情報：実行環境 | AAC同期データから選択、未選択時デフォルト実行環境 | - |
| 備考 | 自由記述 | 最大4000バイト |

## 対話種別

同一目的の対話ファイルをまとめ、OS種別ごとの差異を吸収（抽象化）する分類です。項目: 対話種別名（必須、最大255バイト）、備考。

## 対話ファイル素材集

対話種別とOS種別の組み合わせごとに対話ファイルを登録します（1つの対話種別を複数OSに対応させたい場合は、同じ対話種別で各OS種別に対して個別に登録）。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| 対話種別名 / OS種別 | 登録済みの対話種別・OS種別から選択 | 各必須 |
| 対話ファイル素材 | UTF-8 BOMなし、YAML書式 | 必須、最大100MB |
| ターゲット：Linux/Windows/その他、Python要否 | 用途表示（未選択でも実行に影響なし） | その他は最大4000バイト |
| 説明／説明(en)／備考 | 自由記述 | 各最大4000バイト |

内部処理での変数抽出はリアルタイムでないため、代入値自動登録設定で扱えるまで時間がかかる場合があります。

## Movement-対話種別紐付

Movementでインクルードする対話ファイルに対応した対話種別を管理します（閲覧/登録/更新/廃止）。項目: Movement（必須）、対話種別（必須。作業対象毎にOS種別と対話種別に紐づく対話ファイルが実行対象となる）、インクルード順序（1〜2147483647、昇順で実行、必須）、備考（最大4000バイト）。

## 代入値自動登録設定

パラメータシート項目の設定値とMovementの変数の紐付を管理します（閲覧/登録/更新/廃止）。登録情報は作業実行時に「代入値管理」「作業対象ホスト」に反映されます。項目構成はAnsible-Legacyと同様です: パラメータシート(From) メニュー:項目（必須）、代入順序（バンドル使用時必須）、登録方式（Value型/Key型、必須）、Movement名（必須）、IaC変数(To) Movement名:変数名（必須）、代入順序（複数具体値変数の場合必須、具体値1個でも入力）、NULL連携（True/False、未選択時はインターフェース情報の値を適用）、備考。

代入順序が未入力の変数は通常変数、入力されていれば複数具体値変数として扱われます（連続していなくても詰めて処理される）。代入値自動登録設定で登録した変数のみが作業実行時にホスト変数ファイルへ出力され、対話ファイルで使用中の変数が未登録の場合は作業実行がエラーとなります（Legacyと異なり、未登録変数があると即エラー）。

ファイル埋込変数・テンプレート埋込変数を対話ファイルの変数に紐付ける使用例はAnsible-Legacyと同様です（ファイル管理の`CPF_test`、テンプレート管理の`TPF_sample`をパラメータシート項目値として登録し、代入値自動登録設定でRole内変数に紐付ける）。

## 作業実行 / 作業状態確認 / 作業管理 / 作業対象ホスト / 代入値管理

Ansible-Legacyと同様の操作です。**作業実行**の実行種別: 作業実行（構築作業を実行）、ドライラン（`--check`相当）、パラメータ確認（代入値自動登録設定の情報を反映して確認のみ）。予約日時は未来のみ指定可。

**作業状態確認**: ステータス・実行ログ・エラーログを表示。AAC実行時は機器一覧の各項目でグループ化された単位、さらにオプションパラメータのジョブスライス数で分割され、ログはTab表示（`exec.log`＝全ログ、`exec_<グループ番号>_<通番>`＝分割ログ）。作業対象ホスト確認・代入値確認・緊急停止／予約取消ボタン、ログ検索、投入データ・結果データのダウンロード、収集状況を確認できます。

**作業管理・作業対象ホスト・代入値管理**の項目構成もAnsible-Legacyと同様です。

## 対話ファイルの記述方法

対話ファイルは`conf`セクション（`timeout`パラメータでタイムアウト値1〜3600秒を指定）と`exec_list`セクション（対話モジュールで作業対象への構築処理を記述）の2セクションで構成されます。ITA独自モジュールは実行時にssh/telnet接続を行うため、必要に応じて`exec_list`先頭でパスワード認証処理（`expect: '*assword'` / `exec: 'password'`）が必要です。

### 対話モジュール一覧

| モジュール | 用途 |
|---|---|
| expect | コマンドプロンプトを待受け後、コマンドを投入する。 |
| state | コマンド投入・プロンプト待受け後、標準出力の内容を外部Shellで解析し結果判定する。 |
| command | コマンドを連続投入可能で、投入前後に条件分岐を行える。 |
| localaction | Ansible Core/AAC/Agentの実行環境上でコマンドを投入する。 |

**expectモジュール**: `expect`（必須、コマンドプロンプト、正規表現可。timeout内に受け取れない場合は異常終了）と`exec`（必須、投入コマンド）を交互に指定。例: `- expect: '*assword'` / `exec: 'password'`。

**stateモジュール**: `state`（必須、投入コマンド）、`prompt`（必須、コマンドプロンプト、正規表現可）、`shell`（任意、結果判定用の自作shellファイル名。exitコード0で正常、他は異常。省略時はデフォルトshellが`parameter`の文字列で標準出力をgrepし、1行でもマッチすれば正常）、`parameter`（任意、検索文字列。複数指定可。shell使用時は起動引数`$2`以降になる）、`stdout_file`（任意、標準出力の退避先。省略時はITA自動生成ファイル名）、`success_exit`（任意、yesで正常時に即正常終了、デフォルトno）、`ignore_errors`（任意、yesで異常でも次の処理に進む、デフォルトno）。ユーザshellは`$1`=stdout_file、`$2`以降=parameterの内容で起動される。

**commandモジュール**: `command`（必須、投入コマンド）、`prompt`（必須、コマンドプロンプト、正規表現可）、`timeout`（任意、省略時は`conf.timeout`）、`register`（任意、標準出力を退避する変数名。when/exec_when/failed_whenでのみ使用可、1つのみ保持）、`with_items`（任意、複数具体値変数名を指定してコマンドを連続投入。`{{ item.X }}`（X=0〜99）で参照。各変数の具体値数が異なる場合は最大数でループし不足分はnull扱い。promptとtimeoutで使う変数はcommandより1個多い具体値が必要）、`when`（任意、投入前の条件判定。マッチすればコマンド投入、しなければスキップ）、`exec_when`（任意、with_items使用時のループ毎のcontinue条件）、`failed_when`（任意、投入後のstdout内容に対する条件判定。マッチで正常、しなければ異常終了）。

条件式の書式: 変数定義判定（`VAR_xx is define` / `is undefine`）、変数具体値判定（`VAR_xxまたはregister変数 比較演算子 文字列/VAR_xx`、比較演算子は`==` `!=` `>` `>=` `<` `<=`）、`match(正規表現)` / `no match(正規表現)`、`failed_when`では`stdout 比較演算子 文字列`も使用可。OR条件は同一行に`OR`で記述、AND条件は複数行に分けて記述。

**localactionモジュール**: `localaction`（必須、投入コマンド。`conf.timeout`は適用外で完了まで次に進まない）、`ignore_errors`（任意、デフォルトno）。実行エンジン側（Ansible Core/AAC/Agent）でのファイル操作等に利用（例: `{{ __workflowdir__ }}`配下へのディレクトリ作成）。

### 正規表現とエスケープ

`expect`の`expect`、`state`の`prompt`、`command`の`prompt`、`when`/`exec_when`/`failed_when`の`match()`は正規表現として評価されます。`\` `*` `.` `+` `?` `|` `{}` `()` `[]` `^` `$`を含む場合はエスケープ文字`\`が必要です。

### 注意事項

- `prompt`に後方一致`.*`を使うと標準出力が空になるため使用しないこと。
- 対話的なコマンド（`ssh-keygen`等）は`command`/`state`モジュールでは処理できず、`expect`モジュールで作成すること。
- 複数具体値変数が使用できるのは`command`モジュールの`with_items`のみ（他パラメータで使用するとエラー）。
- 対話ファイルの最終行には必ず`exit`を投入すること（省略すると最終処理完了後すぐにセッションが切断され、時間のかかる処理が異常終了する場合がある）。
- 各モジュールのパラメータ全体はYAML構文上、クォーテーションで囲むこと（変数を含む場合や、終端が`:`となる定数のみの場合など）。
- ログインユーザのLANGはUTF-8/euc/shift_jisをサポート（機器一覧のLANGで設定）。euc/shift_jisは一部全角文字（丸数字等）がUTF-8にデコードできず`??`表示になったり、`expect`の待ち受けがタイムアウトする場合がある。
- コマンド終端コードは「LF」を送信する。作業対象の終端コードが「CRLF」の場合、投入コマンド末尾に`\r`を追加すること。
- 作業対象のコマンドプロンプト直前にOperating System Commandシーケンスが付加される場合があるが、ITAが`prompt`直前のエスケープシーケンスを排除する。

## 付録: Ansible実行時の投入データ・結果データ

投入データはZIP形式で作業状態確認からダウンロード可能です（機器一覧のパスワードやSensitive設定Trueの変数はansible-vaultで暗号化）。主な対応関係: 対話ファイル→`/child_playbooks`、テンプレート/ファイル素材→`/template_files`/`/copy_files`、代入値管理の具体値（ファイル）→`/upload_files`、各種変数・機器情報→`/host_vars`、ssh鍵ファイル→`/ssh_key_files`、オプションパラメータ/並列実行数→`/AnsibleExecOption.txt`（Core/AAC）または`/env/cmdline`（Agent）、機器一覧の接続情報→`/hosts`（Core/AAC）または`/inventory/hosts`（Agent）、機器一覧の接続オプション→`/host_vars`、対話ファイル・インクルード順序→`/playbook.yml`、実行環境関連ファイル（Agent利用時のみ）→`builder_executable_files/`、`runner_executable_files/`。

結果データの主なファイル: `result.txt`（Core限定）、`xxx.pid`（ansible-playbookプロセスID、Core/Agent）、`pioneer.xxx`（Pioneerモジュールのプロセスログ、全エンジン共通）、`xxx_private.log`（Pioneerモジュールのログ、全エンジン共通）、`error.log`/`exec.log.org`/`exec.log`（全エンジン共通）、`exec_<作業番号>_<グループ番号>`（AAC限定の分割ログ）、`forced.txt`（緊急停止記録、Core/Agent）、`user_files`（`__workflowdir__`出力先、全エンジン共通）、`child_exec.log`/`child_error.log`（ansible-builder実行ログ、Agent限定）。

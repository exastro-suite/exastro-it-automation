# 収集機能の設定と利用方法

収集機能とは、ITAで実施したAnsible-Driverの作業実行結果（規定フォーマットで出力されたソースファイル）を元に、パラメータシートへ値を自動登録する機能です。ソースファイルを生成するIaC（Playbook、Role）は各ユーザーが準備する必要があります（参考: Ansible Playbook Collection）。

## 動作要件

以下がITAに設定されている必要があります。

- パラメータシート（ホスト/オペレーションあり）が作成されている。
- 収集項目値管理で作業実行結果（ソースファイル）とパラメータシートの項目の紐付設定がされている。
- 収集対象機器（ホスト名）が機器一覧に登録済み。

作業実行後、以下の状態であればパラメータシートへの登録を実施します。

- 作業実行が正常に完了している。
- 作業実行結果として規定の構造でディレクトリ・ファイルが配置されている。

## 収集対象ディレクトリ・ファイル構造

収集対象のソースファイルはYAML形式で出力します（例: `VAR_RH_sshd_config: [{key: PermitRootLogin, value: yes}, ...]`）。

出力先ディレクトリはIaC内で以下のITA独自変数として扱えます。

| ITA独自変数 | 変換先 |
|---|---|
| `__parameter_dir__` | 作業結果ディレクトリ配下の`_parameters` |
| `__parameters_file_dir__` | 作業結果ディレクトリ配下の`_parameters_file` |
| `__parameters_dir_for_epc__` | 作業ディレクトリ配下の`_parameters` |
| `__parameters_file_dir_for_epc__` | 作業ディレクトリ配下の`_parameters_file` |

ディレクトリ構造: `_parameters/<ホスト名>/<収集対象ファイル>`、`_parameters_file/<ホスト名>/<アップロード対象ファイル>`（`_parameters_file`はファイルアップロード用、名称固定）。上位ディレクトリはAnsible-Driverの実行モードに依存し、`/storage/<Organization>/<Workspace>/driver/ansible/<モード識別子>/<作業No>/in（または out）/`となります（モード識別子: legacy / pioneer / legacy_role）。上記のITA独自変数を使わない場合は、Playbook側でこの構造を認識して出力先を記述する必要があります。

ファイルアップロード対象パラメータシートを収集する場合、ソースファイル内の変数値（ファイル名/パス）に対応するファイルが`_parameters_file`配下に配置されている必要があります。指定方式:

| 指定方式 | 記載例 | 備考 |
|---|---|---|
| ファイル名指定 | `VAR_FILE_NAME: 'ファイル名'` | 複数該当時は対象ファイルがランダムになる |
| ファイルパス指定（後方一致） | `VAR_FILE_NAME: '/<階層X>/<ファイル名>'` | 複数該当時は対象ファイルがランダムになる |

ファイル削除は、対象変数の値を空文字（`""`）に設定することで行います。

## 取り扱う変数の種類

ソースファイル内で扱える変数は3種類です。

- **通常変数**: `VAR_users: root`（具体値を1つ定義）
- **複数具体値変数**: `VAR_users: [root, mysql]`（具体値を複数定義）
- **多段変数**: `VAR_users: [{user-name: alice, authorized: password}]`（階層化された変数、`user-name`等がメンバ変数）

変数名には`" . [ ] ' \ :`の7文字を除くASCII文字(0x20〜0x7e)が使用できます（先頭に使えない文字はクォーテーションで囲む必要あり）。

## メニュー構成

- **Ansible共通 → 収集項目値管理**: 作業実行の出力結果（ソースファイル）とパラメータシートの項目の紐付設定を行い、収集機能で登録する対象パラメータを管理します。
- **Ansible-Legacy／Ansible-LegacyRole／Ansible-Pioneer → 作業管理**: 作業実行履歴を管理し、収集機能によるパラメータシートの登録状況・実行ログを参照します。

## 作業フロー

1. パラメータシート（ホスト/オペレーションあり）を作成。
2. 収集項目値管理でソースファイルとパラメータシート項目の紐付情報を登録。
3. 作業準備・作業実行（オペレーション・Movement・ワークフローを選択して実行）。
4. 完了した作業Noを対象に収集機能（BackYard）がパラメータシートへの登録処理を実施。
5. 各モードの作業管理画面で収集状況・ログを確認。

## 収集項目値管理

収集項目とパラメータシート項目の紐付設定を行います。

**収集項目(From)**: パース形式（YAML形式のファイルを解析、必須）、PREFIX（ファイル名、拡張子除く、必須）、変数名（収集対象の変数名、必須。配列/ハッシュ構造の場合メンバ変数の入力も必須）、メンバ変数（複数具体値・多段変数の場合に入力）。

**パラメータシート(To)**: メニューグループ:メニュー:項目（「:」区切りで表示される項目を選択）。同一のパラメータシート項目に対して複数の「PREFIX-変数名」を設定している場合、ファイル名の昇順で処理されます。

**設定例**:
- 通常変数（`SAMPLE.yml`に`VAR_sample_config_1: yes`）: PREFIX=`SAMPLE`、変数名=`VAR_sample_config_1`
- 複数具体値変数（`VAR_sample2_conf: [SAMPLE1, SAMPLE2, SAMPLE3]`）: メンバ変数=`[0]`, `[1]`, `[2]`
- 多段変数（`VAR_RH_sshd_config: [{key:.., value:..}, ...]`）: メンバ変数=`[0].key`, `[0].value`, `[1].key`, `[1].value`
- 深いネスト（`VAR_RH_snmpd_info.com2sec[]`配下に`sec_name`等）: メンバ変数=`com2sec[0].sec_name`等

## 収集状況の確認

各モードの作業管理画面で確認できるステータス: 「対象外」（対象ファイルなし）、「収集済み」（実施済み）、「収集済み（通知あり）」（登録/更新中に不備あり）、「収集エラー」（Movementのオペレーション・ホストに不備あり）。作業状態が「完了」でない場合、収集状況は更新されず空のままです。「収集ログ」から実行ログをダウンロードできます（例: 登録失敗時は`{'item_1': [{...'msg': 'Regular expression error...'}]}`、`Operation is abolished, so registration and update processing is skipped`、対象ファイルなしの場合`There is no file in the collection target directory.`等が出力される）。

## BackYardの登録処理概要

1. 収集対象ステータスが「完了」の作業一覧を取得。
2. 対象作業Noからオペレーション情報・対象ホスト・対象ソースファイルを取得。
3. 対象ホストが機器一覧に登録済みか確認（登録＝収集対象、未登録＝対象外）。
4. 対象ソースファイルと収集項目値管理から対象パラメータシートのメニューIDを取得（複数ファイルはファイル名昇順で処理）。
5. 登録・更新用パラメータを生成し、オペレーション・ホストの組み合わせで一意データの有無から登録/更新を判定。
6. パラメータシートへデータを登録・更新。
7. 作業Noの収集状況ステータスを更新。

登録タイミングはBackYardの実行プロセス周期に依存します。

## 収集対象ファイルの値の取り扱い（データ型変換）

YAML内の値はパラメータシートの項目（文字列単一行想定）に登録される際、以下のように変換されます。

| YAML記述 | 登録される文字列値 |
|---|---|
| `TEST`（クォートなし）, `'TEST1'`, `"TEST2"` | そのまま文字列（`TEST`, `TEST1`, `TEST2`） |
| `null`, `NULL`, 空値 | `null`（データ型もnull） |
| `"null"`, `"NULL"` | 文字列`"null"`, `"NULL"` |
| `true`, `false`, `YES`, `NO`（クォートなし） | 文字列`"true"`, `"false"` |
| `"true"`, `"false"`, `"YES"`, `"NO"`（クォートあり） | それぞれの文字列そのまま |
| `''`, `""`（空文字） | 空文字`""` |
| `100`（数値） | 文字列`"100"` |

## 複数の同一ファイル名の扱い

同一ホスト配下の異なる階層に同名ファイルが複数存在する場合、ファイル名のみの指定（例: `VAR_upload_file_1: config`）では対象がランダムに選ばれます。パス指定（後方一致、例: `'/APP002/config'`）で該当が複数あれば同様にランダムになりますが、より深い階層まで指定すれば一意に絞り込めます（例: `'/APP003/APP002/config'`は該当パスのみに一意対応）。

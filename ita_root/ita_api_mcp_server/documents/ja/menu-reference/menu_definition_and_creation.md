# パラメータシート定義に関するリファレンス(menu_definition_and_creation.md)

- **重要** パラメータシートの定義はパラメータシート作成前に必ずユーザーに確認を取ること
- **重要** パラメーターシートタイプ（sheet_type_id）、ホストグループ(hostgroup)、バンドル(vertical)はパラメータシート作成後の変更は行えない
- **重要** 各項目の「必須(required)」設定は、パラメータシート作成後に変更できない。requiredは作成時に確定させること。

- **重要（遵守確認）** パラメータシート定義を提案する際は、本リファレンスを読んだ証跡として、
  提案の中に必ず次の「定義前チェック結果」を明記すること（省略不可）。
  この結果を提示せずに create-menu を呼び出してはならない。
    1. 使用予定の全Playbook（またはMovementに紐付く全モジュール）の変数と型の一覧
       （各変数が「リスト型」か「単一値」かを明記）
    2. sheet_type_id / hostgroup / vertical の確定値と、その根拠
       （特に vertical は下記「バンドル(vertical)判定手順」の結果を引用すること）
    3. 上記が作成後に変更不可である旨の確認

- 項目定義に関する留意事項
    - 使用する予定のPlaybookの変数や変数の型を確認してそれに合わせた項目定義を行うこと

- パラメーターシートタイプ（sheet_type_id）に関する留意事項
    - 作業実行に関するパラメーターシートは基本的にホスト/オペレーションあり(sheet_type_id: "1")を使用する
    - データの蓄積や収集機能の出力先のパラメーターシートとして使用するものに関してはデータシート(sheet_type_id: "2")を使用する

- バンドルに関する留意事項
    - バンドルを有効にすると、同一の「ホスト名」×「オペレーション」(またはオペレーション単体)の組み合わせに対して、同じ項目セットを縦に繰り返し登録できる(リピート行/縦持ち)
    - 使用する予定のPlaybookの変数や変数の型がリスト形式である場合、バンドルの使用をユーザーに提案して確認する
    - バンドルを無効にすると同一の「ホスト名」×「オペレーション」(またはオペレーション単体)でユニーク制約が付くようになる
    - バンドルを有効にすると同一の「ホスト名」×「オペレーション」(またはオペレーション単体)の他に代入順序`input_order`でユニーク制約が付くようになる
    - データシート(sheet_type_id: "2")ではバンドル利用は不可
    - 代入順序`input_order`は、代入値自動項目設定の`column_substitution_order`で指定することで値をPlaybook等に連携することができるようになる

- **重要（リスト型変数と単一値変数が混在する場合の設計）**
    - バンドル(vertical:1)では、同一「ホスト名×オペレーション」に対し項目セットを複数行(input_order)で登録する。
      このとき、リスト型変数へ複数要素を渡すために行を増やすと、同じ行に含まれる単一値項目にも値の入力可否が発生する。
    - リスト型変数（複数行にしたい項目）と単一値変数（1行で足りる項目）が混在する場合、単一値項目は required:"0"（任意）で作成すること。
      そうすれば、2行目以降で単一値項目を空欄にでき、「単一値変数が意図せず複数要素リスト化する」ことを防げる。
    - required は作成後に変更できないため、この判断は必ず定義時に行うこと。
    - 判定の目安:
        | 項目が連携する変数 | 行数 | required 推奨 |
        |---|---|---|
        | リスト型（複数要素を渡す） | 複数行 | 用途に応じて（各行で入力する項目は "1" 可）|
        | 単一値（1要素で足りる） | 1行のみ入力 | "0"（任意）にして2行目以降を空欄可能に |

- **バンドル(vertical)判定手順（create-menu実行前に必ず実施し、結果を上記「定義前チェック結果」に記載すること）**
    1. 使用予定の全変数の型（リスト型 / 単一値）を洗い出す。
    2. 「1つの『ホスト名』×『オペレーション』の組み合わせに対して、
       ある項目へ複数の値をリストとして渡したい」または
       「ユーザーが“値ごと／要素ごとにレコード（行）を分けたい”と述べている」場合は
       → **バンドル(vertical:1)が必須**。非バンドル(vertical:0)では実現できない。
    3. すべての変数が単一値で、1組み合わせ=1レコードで足りる場合は vertical:0 を選ぶ。

- **非バンドル(vertical:0)でリスト化しようとした場合の失敗（頻出のアンチパターン）**
    - vertical:0 は「ホスト名 × オペレーション」にユニーク制約が付くため、
      **同一の組み合わせでは1レコードしか登録できない**。
      よって「値ごと・要素ごとにレコードを分けてリスト連携する」ことは構造上不可能。
    - この状態で maintenance-all にレコードを分けて渡すと、次のエラーになる:
      `The combination is incorrect. (Combination: {'operation_name_select': ..., 'host_name': ...})`
    - このエラー、または「リスト型変数へ複数値を渡したいのに vertical:0 になっている」ことに
      気づいたら、設計をバンドル(vertical:1)に見直すこと。
    - なお、リスト型変数へ複数値を渡す必要がある場合の既定解は vertical:1 である。
      1項目への集約（例: カンマ区切り）で回避する場合は、その集約形式を
      対象モジュール/Playbookが複数値として解釈することを本文（YAML）で必ず確認すること。

- **vertical 判定早見表**
    | 変数の型／ユーザー要件                         | レコードの持たせ方         | vertical   |
    |------------------------------------------------|---------------------------|------------|
    | すべて単一値                                   | 1組み合わせ=1レコード     | 0          |
    | リスト型を1組み合わせで複数要素として渡したい  | 項目を縦に複数行で入力     | 1（必須）  |
    | 値ごと/要素ごとにレコードを分けたい            | 縦持ち（バンドル）         | 1（必須）  |
    ※ 「複数値を1セルに集約して単一項目で渡す」構成は、対象Ansibleモジュール（またはPlaybook）の該当引数がその集約形式を複数値として解釈する実装である場合に限り検討可。
      集約可否は必ず実際のPlaybook/モジュール仕様を確認して判断し、画一的に「カンマ区切りで妥協可」と決めつけないこと。
      判断できない場合や複数要素を確実に渡したい場合は vertical:1 を選ぶこと。

- **リスト型変数とバンドルの連携補足**
    - バンドルの1項目に複数行を入力し、それらを1つのリスト変数の複数要素として渡す場合、代入値自動登録設定は「行数分」のレコードが必要
      （詳細はsubst_value_auto_reg_setting_ansible_legacy のリファレンス参照）。

# CI/CD For IaC機能の設定と利用方法

## 用語

- **紐付元資材**: CI/CD For IaC機能で連携するGitリポジトリ内の資材。
- **紐付先資材**: Ansible-Driver・Terraform-Cloud/EP-Driver・Terraform-CLI-Driverの以下メニューからアップロードする資材: Ansible-Legacy/Playbook素材集、Ansible-Pioneer/対話ファイル素材集、Ansible-LegacyRole/ロールパッケージ管理、Ansible共通/ファイル管理、Ansible共通/テンプレート管理、Terraform-Cloud-EP/Module素材集、Terraform-Cloud-EP/Policy管理、Terraform-CLI/Module素材集。

## 機能概要

CI/CD For IaC機能は2つの機能から構成されます。

1. **Git連携機能**: ITA内にGitリポジトリのクローンを作成し、定期的に紐付元資材の更新を検知して「リモートリポジトリ資材」メニューに一覧化します。
2. **資材紐付機能**: 紐付元資材と紐付先資材の紐付を登録し、紐付先資材の動作検証用のオペレーション・Movementを登録します。紐付元資材が更新されると紐付先資材が自動更新され、検証用オペレーション・Movementで作業実行が行われます。

## メニュー構成

| No | メニュー・画面 | 概要 |
|---|---|---|
| 1 | リモートリポジトリ | Gitリポジトリの情報を管理。 |
| 2 | リモートリポジトリ資材 | Gitリポジトリの資材情報を管理（インストール時は非表示メニュー）。 |
| 3 | 資材紐付 | 紐付元資材と紐付先資材の紐付情報を管理。 |

## 作業フロー

1. リモートリポジトリを登録（連携するGitリポジトリ情報）。
2. 資材紐付を登録（紐付元資材と紐付先資材の紐付）。
3. 必要に応じて資材紐付にオペレーション+Movementを登録（更新時の動作検証用）。
4. 紐付元資材更新時の紐付先資材自動更新と、動作検証（作業実行）が行われることを確認。

## リモートリポジトリ

連携するGitリポジトリの情報を登録します。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| リモートリポジトリ名 | 任意の名称 | 必須、最大255バイト |
| リモートリポジトリ(URL) | `git clone`に指定するURL | 必須、最大255バイト |
| ブランチ | クローン対象ブランチ（未入力時はdefaultブランチ） | 最大255バイト |
| プロトコル | https／sshパスワード認証／ssh鍵認証(パスフレーズなし・あり、現在使用不可) | 必須 |
| Visibilityタイプ | Public/Private（プロトコルがhttpsの場合必須） | - |
| Gitアカウント：ユーザー/パスワード | Visibility=Privateの場合必須。GitHubはパスワード認証廃止のため個人アクセストークンを使用 | 各最大255バイト |
| ssh接続情報：パスワード | ssh鍵のLinuxユーザパスワード（sshパスワード認証時必須） | 最大255バイト |
| ssh接続情報：パスフレーズ | 鍵ファイルのパスフレーズ（ssh鍵認証時必須） | 最大255バイト |
| ssh接続情報：接続パラメータ | 環境変数`GIT_SSH_COMMAND`に設定するパラメータ（Git 2.3以降で有効。デフォルトで`UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no`相当が付与される） | 最大4000バイト |
| Proxy：Address/Port | プロキシ環境下でGitサーバに疎通するために設定 | Address最大255バイト |
| リモートリポジトリ同期情報：自動同期 | True＝周期的に同期、False＝自動同期しない | 必須、初期値：有効 |
| リモートリポジトリ同期情報：周期(秒) | 未入力時デフォルト60秒 | 単位:秒 |
| 通信リトライ情報：回数/周期(ms) | 未入力時デフォルト3回/1000ms | - |
| 備考 | 自由記述 | 最大4000バイト |

同期状態の表示項目: 状態（空白＝新規登録・更新・廃止復活直後／正常／異常＝同期停止中／再開＝再開ボタン押下後）、詳細情報（異常時の原因、再開または更新でクリア）、最終日時（最終同期日時、再開または更新でクリア）、再開ボタン（異常時のみ活性）。

## 資材紐付

紐付元資材と紐付先資材を紐付け、紐付先資材の動作検証用オペレーション・Movementを登録します。紐付元資材更新時、内部機能が紐付先資材を自動更新し、検証用オペレーション・Movementで作業実行して結果を表示します。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| 紐付先資材名 | 紐付先資材タイプにより下記メニューの項目に紐付く名称。各メニューの入力規則に従う | 必須、最大255バイト |
| Gitリポジトリ(From)：資材パス | リモートリポジトリメニューに登録された資材パスから選択 | 必須 |
| Exastro ITautomation(To)：紐付先資材タイプ | 対応するドライバのインストールが必要（下表参照） | 必須 |
| テンプレート管理：変数定義 | 紐付先資材タイプが「Ansible共通/テンプレート管理」の場合に必要な変数定義を入力（他タイプでは不要） | 最大4000バイト |
| Ansible-Pioneer：対話種別／OS種別 | 紐付先資材タイプが「Ansible-Pioneer/対話ファイル素材集」の場合に選択（他タイプでは不要） | - |
| 素材同期情報：自動同期 | True＝Git更新時に紐付先資材を自動更新、False＝更新しない | 必須、初期値：有効 |
| デリバリ情報：オペレーション／Movement | 紐付先資材更新時に作業実行するオペレーション・Movementを選択 | - |
| デリバリ情報：ドライラン | True＝ドライランモード（Ansibleはドライラン、Terraformはplan確認）で実行、False/未選択＝通常実行 | - |
| 備考 | 自由記述 | 最大4000バイト |

紐付先資材タイプとメニュー項目・必要ドライバの対応:

| メニュー | 項目 | 必要ドライバ |
|---|---|---|
| Ansible-Legacy/Playbook素材集 | Playbook素材名 | Ansible-Driver |
| Ansible-Pioneer/対話ファイル素材集 | 対象項目なし | Ansible-Driver |
| Ansible-LegacyRole/ロールパッケージ管理 | ロールパッケージ名 | Ansible-Driver |
| Ansible共通/ファイル管理 | ファイル埋込変数名 | Ansible-Driver |
| Ansible共通/テンプレート管理 | テンプレート埋込変数名 | Ansible-Driver |
| Terraform-Cloud-EP/Module素材集・Policy管理 | Module素材名・Policy名 | Terraform-Cloud/EP-Driver |
| Terraform-CLI/Module素材集 | Module素材名 | Terraform-CLI-Driver |

同期状態の表示項目: 資材同期情報の状態（空白／正常／異常＝同期エラーまたは検証用作業実行が失敗／再開）、詳細情報、最終日時、再開ボタン（動作は前述のリモートリポジトリと同様）。デリバリ情報の詳細情報（作業実行失敗時のエラー原因。実行できた場合の異常判定は行わないため、作業状態確認ボタンから各ドライバの作業状態確認で結果を確認する必要がある）、作業インスタンスNo、作業状態確認ボタン（作業実行できた場合のみ活性）。

**紐付先資材の更新処理の流れ**: Gitリポジトリの資材更新を検知 → 差分（備考含む）を比較 → 差分があれば紐付先資材を更新 → デリバリ情報（オペレーション・Movement）が設定されていれば作業実行 → 結果に応じて資材同期情報の状態を「正常」または「異常」（詳細情報にエラー原因）に設定。紐付先資材名を変更した場合、変更前のレコードは残り、変更後の名称で新規レコードが作成されます。

## 非表示メニュー: リモートリポジトリ資材

紐付元資材の一覧が内部機能により自動更新されます（手動でのレコード追加・更新・削除は行わないこと）。表示するには管理コンソールのロール・メニュー紐付管理で復活処理が必要です。項目: リモートリポジトリ名（リスト選択、必須）、資材パス（最大4096バイト、必須。リモートリポジトリの同期状態が「異常」の場合は表示されない）、資材タイプ（Ansible-LegacyRoleの場合「Rolesディレクトリ」、それ以外は「ファイル」）。

## 付録: 資材をGitリポジトリに登録する場合の注意事項

- 256バイト以上の資材名を含むGitリポジトリを登録すると`git clone`が異常終了します。
- ファイルパスを含めて4096バイト以上の資材名を含む場合も`git clone`が異常終了します。

## 付録: ロールパッケージ管理に紐付する資材の注意事項

`roles`という名前のディレクトリを含む親ディレクトリを作成し、その配下にロールパッケージのファイル・ディレクトリを配置する必要があります。ただし、**Gitリポジトリのルートディレクトリ直下**に`roles`ディレクトリを作成しても、ロールパッケージ管理に紐付けるディレクトリとして認識されません（例: ルート直下の`roles`は認識されないが、`sample/roles`のようにサブディレクトリ配下にある場合は認識される）。資材紐付メニューの資材パスには認識された方のパス（例: `sample/roles`）を選択してください。

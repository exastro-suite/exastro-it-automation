# OASE（Operation Autonomy Support Engine）概要

## 機能の概要

OASEとは、外部から取得したイベント情報を分析し、そのイベントへの対処の自動化を支援する機能です。機能フローは以下の通りです。

1. **イベント収集**: 外部サービスからイベントを収集します。イベントはExastro OASE Agentによって収集され、APIを通してITA本体に送信されます。
2. **ラベル付与**: ITAで受信したイベントに対して設定されたラベルを付けます。異なるアプリケーションからのイベント情報をOASE内で均質化して扱うことが目的です。
3. **評価**: 付与されたラベルを用いてイベントを抽出（フィルター）し、設定されたルールにマッチするかどうかを判定します。
4. **アクション実行・通知**: ルールにマッチした際に、設定したアクション（ConductorとOperationの設定）を実行します。アクション実行前後の通知もルールメニューで設定できます。

## 用語の定義

| 用語 | 内容 |
|---|---|
| 監視システム | システムの状態変化を収集するソフトウェア・サービス。状態変化を検知しOASEにイベントを作成・送信する。 |
| OASE | 監視システムが作成したイベントを収集し、定義された条件に基づいて適切なアクションを実行する運用自動化支援ソフトウェア。 |
| イベント | 監視システムから取得した、システムの状態変化の発生情報。 |
| TTL（Time To Live） | イベントがルール評価対象として扱われる期間（秒）。①複数ルールにマッチする場合に優先度の高いルールを適用するため、完全な条件が揃うまで判断を待つ猶予、②TTLの2倍以上経過した古いイベントを即座に「時間切れ」として評価対象から除外する、の2目的で使用。最小値10秒、最大値2147483647秒、デフォルト3600秒。 |
| ラベル | ラベル作成・付与設定に基づき、OASE内部で扱いやすい形（key&value形式）で付与されたイベントのプロパティ。異なるアプリケーションのイベントを均質化する。 |
| 重複排除 | 本質的に同一内容のイベントを複数取得した場合、先頭のイベントのみ取り込む設定。イベント収集システムやOASEエージェントが冗長化されている場合に重複データを扱わないための機能。 |
| フィルター | ラベルの条件から一意のイベントを抽出すること、またはその対象。ルール判定前段階での絞り込みを行う。 |
| ルール | フィルターを組み合わせて作成する、アクション実行や結論イベント生成の条件。 |
| アクション | ルールにマッチした場合にイベントに対して実行する具体的な対応処理。 |
| 評価 | 収集イベントがフィルターで抽出され、ルール条件にマッチするか判定し、マッチ時の次動作（アクション、結論イベント）を決定する一連のプロセス。 |
| 結論イベント | ルールにマッチした際に発生するイベント。元イベントの情報を引き継ぎ処理・判定結果を含み、別ルールでの再評価による連鎖的な自動化が可能。 |

## イベントの状態

| 種類 | 内容 |
|---|---|
| 新規 | 収集後、まだ評価機能に検知されていない状態。判定時間経過後、既知（判定済み）・未知・時間切れのいずれかに変化する。 |
| 既知 | 評価機能に検知された状態・対象。 |
| 既知（判定済み） | ルールにマッチした状態・対象。 |
| 時間切れ | TTLの2倍以上経過して古すぎる、またはTTL経過直後の評価タイミングまでにマッチできなかったため評価対象から外された対象。 |
| 未知 | フィルターに抽出されなかった（評価機能に検知されなかった）状態・対象。今後の評価対象として検討が必要。 |

## イベント種別による通知

| 項目 | 説明 |
|---|---|
| 新規イベント（受信時） | イベント受信時点で通知。重複排除により同一と判断されたイベントは通知されない。 |
| 新規イベント（統合予定） | 重複排除設定のある冗長グループで、最初のイベント受信時に統合通知を送信。後続イベントは統合されるが新たな通知は送信されない。 |
| 新規イベント（判定前） | ルール判定対象となったイベントについて通知。 |
| 既知イベント（判定時） | イベントがいずれかのルールにマッチした際に通知。 |
| 既知イベント（TTL有効期限切れ） | TTL有効期限が切れたイベントについて通知。 |
| 未知イベント | どのルール・条件にもマッチしなかったイベントについて通知。 |

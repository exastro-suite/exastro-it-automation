# ホストグループ機能の設定と利用方法

ホストグループとは、作業対象ホストを論理的な単位（機能・役割）でまとめたグループです。上位を親ホストグループ、下位を子ホストグループと呼び、末端のホストグループが作業対象ホストと紐付きます。階層はホストグループ1つで1階層と数え、頂点から末端まで最大15階層まで定義できます。

## ホストグループの利点：パラメータの継承

親ホストグループに設定したパラメータ（具体値がある場合のみ）は子ホストグループに継承されます。設定箇所を局所化することで付与・変更作業を簡略化できます。子ホストグループを新規追加した場合も、既存の子と同様に親の設定が自動継承されます。

子ホストグループは複数の親ホストグループに紐付けられます。パラメータが重複した場合のルール:

- **異なる階層で重複**: 最も下位のホストグループの値が優先されます（例: 上位dcxと下位zabbix1に同じパラメータがあれば、zabbix1の値が継承される）。
- **同じ階層で重複**: 優先順位が高い（数値が大きい）親ホストグループの値が優先されます。

## 主要機能

ホストグループの設定管理と、パラメータシートのホストグループ単位レコードをホスト単位に分割する機能です。以下の操作を行うと、**全パラメータシートを対象**に分割処理が実行されます: ホストグループ一覧・ホストグループ親子紐付・ホスト紐付管理での登録/更新/廃止/復活。以下の操作では**該当パラメータシートのみ**を対象に分割処理が実行されます: パラメータシート（ホストグループ利用）の登録/更新/廃止/復活、パラメータシート定義・作成でのホストグループ利用選択時の作成/編集/初期化。

## メニュー構成

| メニュー・画面 | 説明 |
|---|---|
| ホストグループ一覧 | ホストグループの登録。 |
| ホストグループ親子紐付 | ホストグループ親子関係の紐付。 |
| ホスト紐付管理 | ホストグループとオペレーションと作業対象ホストの紐付。 |
| ホストグループ分割対象 | ホストグループ単位からホスト単位への分割対象パラメータシート情報と処理状態の管理。 |

## 設定から作業実行までの流れ

1. **パラメータシート作成**: パラメータシート作成機能でホストグループ用パラメータシートメニューを作成する。
2. **ホストグループの登録**（ホストグループ一覧）: 項目はホストグループ名（必須、最大255バイト）、優先順位（0〜2147483647。未入力の場合、同一階層で複数あると優先順序はランダムになる）。
3. **ホストグループ親子関係の定義**（ホストグループ親子紐付）: 親ホストグループ・子ホストグループを選択（両方必須、リスト選択）。親子関係がループする組み合わせ（例: HG1→HG2→HG3→HG1）は登録・更新時にエラーとなります。
4. **ホストグループとオペレーションと作業対象ホストの紐付け**（ホスト紐付管理）: ホストグループ名（必須）、オペレーション（空登録可。空登録の場合は全オペレーションで紐付が有効、指定した場合はそのオペレーションのみ有効）、ホスト名（必須）。この紐付により、ホストグループ内で作業対象ホストを選択する操作が可能になります。
5. **パラメータシートへの登録**（作成したホストグループ用パラメータシート、入力用メニュー）: ホスト名（作業対象ホストまたはホストグループを選択。接頭辞`[H]`＝ホスト、`[HG]`＝ホストグループ、必須）、オペレーション名（必須）、基準日時／実施予定日／最終実行日時（選択したオペレーションに基づき自動表示）、パラメータシートの対象項目（具体値を入力、後述の「代入値の反映」で変数具体値として反映される）。「ホスト名」と「オペレーション」の組み合わせは一意で登録されます（同じホストでも異なるオペレーションとの組み合わせなら登録可能）。
6. **ホスト化**（内部処理、ユーザー操作不要）: 「ホストグループ分解機能」が登録情報をオペレーション毎にまとめ、ホストグループの紐付けに従って作業対象ホスト単位まで継承します。結果は代入値自動登録用メニューグループのメニュー（参照専用、登録/更新/廃止/復活不可）で確認できます。ホストグループと作業対象ホストの両方に項目値が登録されている場合、**作業対象ホストの値が優先**され、作業対象ホスト側が空の場合のみ上位ホストグループの値が継承されます。
7. **オペレーションと作業対象ホストごとの項目の設定値を紐付け**（代入値自動登録設定）: 連携対象のメニュー・項目とMovementの変数を紐付けます（登録/更新/廃止/復活可能）。登録情報は内部処理で「代入値管理」「作業対象ホスト」に反映されます。
8. **オペレーションに紐付く作業対象ホストの反映**（内部処理）: オペレーションに関連する作業対象ホストが自動反映され、「作業対象ホスト」メニューで確認できます。
9. **代入値の反映**（内部処理）: オペレーションごとに、対象MovementのPlaybook・テンプレート内変数へ代入する具体値（手順5で入力した値）が自動反映され、「代入値管理」メニューで確認できます。

## 動作例

ホストグループ`HG_1`（子: `hg_1a`, `hg_1b`）、`HG_2`（子: `hg_2a`, `hg_2b`）を定義し、`hg_1a`→`host_1a`、`hg_1b`→`host_1b`、`hg_2a`→`host_2a`、`hg_2b`→`host_2b`と紐付けた状態で、パラメータシートに以下を登録したとします。

| 作業対象ホスト/ホストグループ | オペレーション | 項目1 | 項目2 |
|---|---|---|---|
| HG_1 | 2023/01/01 00:00_OP1 | 111 | AAA |
| HG_2 | 2023/01/01 00:00_OP1 | ー | BBB |
| host_1a | 2023/01/01 00:00_OP1 | 222 | ー |

ホスト化後、`host_1a`は項目1に自身の登録値`222`（作業対象ホストの値が優先）、項目2は自身が空のため親`HG_1`の`AAA`が継承されます。`host_1b`は項目1・2ともに親`HG_1`の`111`・`AAA`を継承します。`host_2a`・`host_2b`は項目1が親`HG_2`の値が空のため空欄、項目2は`HG_2`の`BBB`を継承します。

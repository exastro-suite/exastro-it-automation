# OASE管理（エージェント・イベント収集・通知テンプレート）の設定

## エージェント概要

エージェント（Exastro OASE Agent）はExastro IT Automation（ITA）とは独立しており、ITA OASEと外部サービスの仲介役として機能します。ITAから対象の外部サービスのイベント収集設定を取得し、その設定を用いて外部サービスからイベントを取得、ITAに送信します。

## エージェント利用手順

1. **イベント収集設定**: OASE管理のイベント収集メニューで、収集対象サービスに関する設定を登録する。
2. **ラベル設定**: OASEのラベル作成/ラベル付与で、ラベル付与の設定を行う（冗長化構成時は重複排除も設定可能）。
3. **エージェントのインストール・起動**: エージェントを起動しイベント収集を開始する。

## 通知テンプレート（共通）の利用手順

1. OASE管理の通知テンプレート（共通）で、OASEの通知に使用するテンプレートをメンテナンス（閲覧/更新）する。
2. Exastroシステムにオーガナイゼーション管理者でログインし、「通知管理」から通知先設定を登録する。
3. 通知先がメールの場合のみ、「メール送信サーバ設定」を登録する。

通知テンプレート（共通）は変更しなくても利用可能です。

## メニュー構成

| No | メニューグループ | メニュー・画面 | 説明 |
|---|---|---|---|
| 1 | OASE管理 | イベント収集 | イベント収集対象の情報を管理します。 |
| 2 | OASE管理 | 通知テンプレート（共通） | OASEの通知で使用する情報を管理します。 |

## イベント収集の設定項目

「OASE管理 → イベント収集」では、イベント収集対象の接続方式・認証方式・TTL等をメンテナンスします。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| イベント収集設定名 | 任意の名称 | 最大255バイト |
| 接続方式 | Bearer認証／パスワード認証／任意の認証／IMAPパスワード認証／エージェント不使用 | - |
| リクエストメソッド | Bearer/パスワード/任意の認証: GET, POST。IMAPパスワード認証: IMAP: Plaintext | - |
| 接続先 | メールサーバはホスト名、APIはURLを入力。Jinja2形式で予約変数使用可 | 最大1024バイト |
| ポート | 接続先のポート | 0〜65535 |
| 認証情報（リクエストヘッダー） | JSON形式、Jinja2予約変数使用可 | 最大4000バイト |
| 認証情報（プロキシ） | プロキシURI | 最大255バイト |
| 認証情報（認証トークン） | Bearer認証のトークン | 最大1024バイト |
| 認証情報（ユーザー名/パスワード） | ログイン情報 | ユーザー名255バイト、パスワード4000バイト |
| 認証情報（メールボックス名） | デフォルトはINBOX | 最大255バイト |
| パラメータ | JSON形式、Jinja2予約変数使用可。GETではクエリパラメータ、POSTではリクエストペイロードとして使用 | 最大255バイト |
| レスポンスキー | レスポンスペイロードからイベントとして受け取るプロパティの親キーをJMESPathで指定 | 最大255バイト |
| レスポンスリストフラグ | レスポンスキーで取得した値が配列かどうか（Trueなら配列分割してイベント化） | - |
| イベントIDキー | イベントをユニーク判別するキー（JMESPathで指定、レスポンスキー以下の階層） | 最大255バイト |
| TTL | ルール評価対象として扱う期間（秒） | 最小10、最大2147483647、デフォルト3600 |
| 備考 | 自由記述 | 最大4000バイト |

接続方式・リクエストメソッド・認証情報の組み合わせ:

| 接続方式 | リクエストメソッド | 認証情報 |
|---|---|---|
| IMAPパスワード認証 | IMAP: Plaintext | ユーザー名・パスワード |
| Bearer認証 | GET, POST | 認証トークン |
| パスワード認証 | GET, POST | ユーザー名・パスワード |
| 任意の認証 | GET, POST | パラメータに記述 |

収集先がメールの場合、文字コードの種類によりデコードできない文字を省いて収集イベントを保存する場合があります（動作確認済み文字コードは後述）。

## 通知テンプレート（共通）の設定項目

「OASE管理 → 通知テンプレート（共通）」でOASEの通知機能で使用するテンプレートをメンテナンスします。利用する通知方法に応じて内容変更や項目追加が必要で、メール以外の通知方法ではフォーマット調整が必須です。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| イベント種別 | 新規イベント（受信時/統合予定/判定前）、既知イベント（判定時/TTL有効期限切れ）、未知イベント（判定時） | 必須 |
| テンプレート | New(received).j2, New(consolidated).j2, New.j2, Known(evaluated).j2, Known(timeout).j2, Undetected.j2 がデフォルト | 最大2MB |
| 通知先 | デフォルトテンプレートには設定不可。デフォルト以外はイベント種別内でユニークな通知先が必要 | - |
| デフォルト | レコードにない通知先への送信時にデフォルトテンプレートを使用 | - |
| 備考 | 自由記述 | 最大4000バイト |

デフォルトのテンプレートはテンプレート・備考のみ更新可能で、廃止もできません。テンプレートはJinja2形式で、`labels.*`（システムラベル）、`exastro_events`、`exastro_agents`、`exastro_edit_count` などの変数を参照できます。**[TITLE]**・**[BODY]** 要素は必須で、これが不足・記述誤りがあると通知は失敗します。編集は[TITLE]・[BODY]要素の内部のみ行い、要素自体を削除・変更しないでください。

## 付録: OASE Agentの.env設定値

| パラメータ | 説明 |
|---|---|
| AGENT_NAME | 起動するOASEエージェント名。内部データベースのファイル名にも使用。 |
| EXASTRO_URL | ITAへのAPIリクエスト先。 |
| EXASTRO_ORGANIZATION_ID | APIリクエスト時のOrganization識別子。 |
| EXASTRO_WORKSPACE_ID | APIリクエスト時のワークスペース識別子。EXASTRO_ORGANIZATION_IDと紐づいたワークスペースが必要。 |
| EXASTRO_REFRESH_TOKEN | Bearer認証のトークン。ユーザーロールはOASE-イベント-イベント履歴メニューをメンテナンス可能である必要がある。 |
| EXASTRO_USERNAME / EXASTRO_PASSWORD | Basic認証情報（REFRESH_TOKEN未使用時、非推奨）。 |
| EVENT_COLLECTION_SETTINGS_NAMES | 取得対象のイベント収集設定名。 |
| ITERATION | ループ処理の回数。 |
| EXECUTE_INTERVAL | ループ処理の実行間隔。 |

設定変更をエージェントに即時反映するには、コンテナ内で `event_collection_settings.json` を削除します（ファイルが存在しない場合、ITAから最新設定を再取得します）。削除しない場合、ITERATIONの数だけループが終了するまで反映されません。

## 付録: レスポンスキー・JMESPath・イベントIDキー

- **レスポンスキー**: レスポンスのペイロードからイベントとして抽出する項目の親キー。JMESPath形式で指定。監視ソフトのレスポンスはJSON形式のみ処理対象。
- **JMESPath**: JSONを対象としたクエリ言語。JSONキーを"."で結合し、配列の場合は`[]`を付ける（例: `value[].name`、`value[].timeseries[].metadatavalues[].name`）。
- **レスポンスリストフラグ**: レスポンスキーで抽出した値が配列ならTrue、それ以外（値やオブジェクト）ならFalse。
- **イベントIDキー**: レスポンスキーで抽出した結果内の、イベントを一意に判別するキー。JMESPath形式で、レスポンスキー抽出後の階層を指定。存在しないキーを指定すると空値になり正しく動作しない。

## 付録: 監視ソフト別のイベント収集設定例

**Zabbix**（例: v6.4.12）: `problem.get` APIをPOSTで呼び出す。接続方式「任意の認証」、レスポンスキー`result`、レスポンスリストフラグ`True`、イベントIDキー`eventid`。認証トークンはZabbixユーザー（専用ユーザー作成推奨）の`user.login`で取得。

**Grafana**（例: v10.3、データソースPrometheus 2.49）: alerts APIをGETで呼び出す。接続方式「Bearer認証」、レスポンスキー`data.alerts`、レスポンスリストフラグ`True`、イベントIDキー`activeAt`。認証トークンはGrafanaのService account tokenで取得（Administration > Service accounts）。

監視ソフトのバージョンによりHTTP API仕様が異なるため、利用バージョンの仕様を確認してください。

## 付録: 利用可能な予約変数

「接続先」「リクエストヘッダー」「パラメータ」で使用可能な予約変数:

| 変数名 | 説明 |
|---|---|
| EXASTRO_LAST_FETCHED_TIMESTAMP | 前回取得時日時（UNIXタイムスタンプ） |
| EXASTRO_LAST_FETCHED_DD_MM_YY / EXASTRO_LAST_FETCHED_YY_MM_DD | 前回取得時日時（各形式） |
| EXASTRO_LAST_FETCHED_EVENT_IS_EXIST | 前回取得イベントの存在フラグ（True/False） |
| EXASTRO_LAST_FETCHED_EVENT | 前回取得イベントのrawデータ。JMESPath形式でプロパティを参照可能（例: `EXASTRO_LAST_FETCHED_EVENT.clock`） |
| EXASTRO_EVENT_COLLECTION_SETTING | イベント収集設定の各項目を参照（`.URL`, `.PORT`, `.AUTH_TOKEN`, `.USERNAME`, `.PASSWORD`, `.PARAMETER`, `.RESPONSE_KEY`, `.RESPONSE_LIST_FLAG`, `.EVENT_ID_KEY`, `.TTL` など） |
| EXASTRO_LAST_FETCHED_TIME / EXASTRO_CURRENT_TIME | 前回取得時刻／現在時刻（YYYY-MM-DD HH:MM:SS形式） |

使用例: 接続先URLへの認証トークン埋め込み（`?token={{ EXASTRO_EVENT_COLLECTION_SETTING.AUTH_TOKEN | urlencode() }}`）、リクエストヘッダーへのBearerトークン埋め込み、パラメータでの現在/前回日時によるフィルタ条件指定、前回取得イベントの有無による条件分岐（`{% if EXASTRO_LAST_FETCHED_EVENT_IS_EXIST %}`）。

## 付録: 通知テンプレート（ServiceNowレコード登録）の設定例

ServiceNow(レコード登録)を通知方法とする場合、TITLEの内容は使用されず、BODYにServiceNoのREST APIレコード登録のリクエストボディ形式で記載します。埋め込みデータにダブルクォートやバックスラッシュが含まれるとエラーになるため、`replace('\\', '\\\\')` や `replace('"', '\\\"')` フィルタで回避します。TAB/LF/CR以外の制御コード（\x01〜\x1f）が含まれる場合もエラーとなるため、`replace('\x01', '')` のようなフィルタで除去します。

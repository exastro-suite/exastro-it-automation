# Ansible-LegacyRoleの設定と利用方法

Ansible-LegacyRoleは、Legacyモードと同様にAnsible標準機能で設定投入しますが、構築コードをパッケージ（Role）として登録し、作業パターンをRoleの組み合わせで構成します。製品部門提供のRoleパッケージによるインストール・環境構築などに使われます。

## メニュー構成

基本コンソール・Ansible共通のメニューに加え、Ansible-LegacyRole独自メニュー: Movement一覧、ロールパッケージ管理（ロールパッケージの管理）、Movement-ロール紐付（Movementでインクルードするロールパッケージの管理）、変数ネスト管理（多段変数が繰返配列で構成される場合の最大繰返数の管理）、代入値自動登録設定、作業実行、作業管理、作業状態確認、作業対象ホスト、代入値管理、ロール名管理／Movement-変数紐付／多段変数メンバー管理／多段変数配列組合せ管理（いずれも非表示メニュー、内部処理用）。

## 作業フロー

1. 機器一覧に接続情報、オペレーション一覧にオペレーション名を登録。
2. 必要に応じてAAPホスト情報・インターフェース情報・実行環境関連（テンプレート/パラメータシート/実行環境管理）を登録。
3. Movementを登録し、ロールパッケージを登録。
4. 必要に応じてグローバル変数・テンプレート・ファイル素材・管理対象外変数を登録。
5. Movement-ロール紐付でMovementにロールパッケージを紐付ける。
6. 必要に応じて変数ネスト管理で多段変数の最大繰返数を登録。
7. パラメータシートを作成・データ登録し、代入値自動登録設定でMovementの変数と紐付ける。
8. 作業実行 → 作業状態確認 → 作業管理で履歴確認。

## Movement一覧

項目はAnsible-Legacyと同様です: MovementID（自動採番）、Movement名（必須、最大255バイト）、遅延タイマー（0〜2147483647、単位分）、Ansible利用情報（ホスト指定形式必須、WinRM接続、ヘッダーセクション最大4000バイト・未入力時デフォルトは`hosts: all` `remote_user: "{{ __loginuser__ }}"` `gather_facts: no` `become: yes`（winrm時become省略）、オプションパラメータ最大4000バイト、ansible.cfg最大100MB）、Ansible Execution Agent利用情報（実行環境：Agent利用時必須、ansible-builderパラメータ最大4000バイト）、Ansible Automation Controller利用情報（実行環境：AAC同期データから選択、未選択時デフォルト実行環境）、備考（最大4000バイト）。`become: yes`設定時は対象ホストのsudo権限をNOPASSWD付きで設定する必要があります。

## ロールパッケージ管理

ユーザ作成のロールパッケージファイル（zip、rolesディレクトリのある階層を圧縮したもの）をメンテナンス（閲覧/登録/更新/廃止）します。

| 項目 | 説明 | 制約事項 |
|---|---|---|
| ロールパッケージ名 | 任意の名称 | 必須、最大255バイト |
| ロールパッケージファイル | zip形式（内包Playbookファイルは UTF-8 BOMなし） | 必須、最大100MB |
| ターゲット：Linux/Windows/その他 | 対応OS（未選択でも実行に影響なし） | その他は最大4000バイト |
| Python要否 | 必要なら「＊」（未選択でも影響なし） | - |
| 説明／説明(en)／備考 | 自由記述 | 各最大4000バイト |

内部処理での変数抽出はリアルタイムでないため反映まで時間がかかる場合があります。**Movement単位での変数名の一意管理**: 変数抜出対象資材から抜出した変数名はMovement単位で一意管理されます。同一ロールパッケージ内で異なるロールが同じ変数名を使い、変数構造（通常変数/多段変数の構造）が異なる場合は登録エラーとなります（メンバー変数の記載順序の違いのみなら問題なし、通常変数と多段変数の混在や多段構造の違いはエラー）。ロールパッケージが異なれば同名でも問題ありません。

## Movement-ロール紐付

Movementでインクルードするロールパッケージを管理（閲覧/登録/更新/廃止）します。項目: Movement（リスト選択、必須）、ロールパッケージ名:ロール名（同一Movementに複数ロールパッケージは登録不可、必須）、インクルード順序（1〜2147483647、昇順で実行、必須）、備考（最大4000バイト）。

## 変数ネスト管理

ロールパッケージの多段変数のうち繰返配列が定義されているメンバー変数の配列の最大繰返数を閲覧・更新します。項目: 最大繰返数（1〜1024、上限は管理コンソールの識別ID「MAXIMUM_ITERATION_ANSIBLE-LEGACYROLE」で変更可能、必須）、備考（最大4000バイト）。初期登録・更新は内部処理でロールパッケージ内の多段変数繰返配列から行われ、リアルタイムではないため代入値自動登録設定で変数が扱えるまで時間がかかる場合があります。

## 代入値自動登録設定

パラメータシート項目の設定値とMovementの変数の紐付を管理します（閲覧/登録/更新/廃止）。登録情報は作業実行時に「代入値管理」「作業対象ホスト」に反映されます。

| 項目 | 説明 | 必須 |
|---|---|---|
| パラメータシート(From) メニュー:項目 | パラメータシート（ホスト/オペレーションあり）の項目 | 〇 |
| パラメータシート(From) 代入順序 | バンドル使用時のみ | バンドル使用時必須 |
| 登録方式 | Value型／Key型 | 〇 |
| Movement名 | 登録したMovement | 〇 |
| IaC変数(To) Movement名:変数名 | Movement-ロール紐付の資材で使用している変数 | 〇 |
| IaC変数(To) Movement名:変数名:メンバー変数 | 多段変数選択時のメンバー変数（具体値を必要とする変数のみ表示、階層は「.」区切り、繰返配列は「[]」で位置0〜を表示） | 多段変数選択時必須 |
| IaC変数(To) 代入順序 | 複数具体値変数の場合の代入順序（1〜、具体値1個でも入力必須） | 複数具体値変数の場合必須 |
| NULL連携 | True/False。未選択時はインターフェース情報の値を適用 | - |
| 備考 | 自由記述 | 最大4000バイト |

**メンバー変数の選択例**: `defaults/main.yml`に`VAR_aaaa`配下に`name`, `object`, `directory`, `password`, `user.root.dev`, `user.root.prod`等をネストして定義すると、変数ネスト管理には`0`, `0.directory`, `0.password`, `0.user.root`, `0.user.root.dev`, `0.user.root.prod`（最大繰返数1）が登録され、代入値自動登録設定では`[0].name`, `[0].object`, `[0].directory[0].create_dir`, `[0].user.root[0].prod[0].prod_user`等が選択可能になります。変数ネスト管理で`0.user.root.prod`の最大繰返数を1→3に更新すると、`[0].user.root[0].prod[1].prod_user`, `[0].user.root[0].prod[2].prod_user`が追加で選択可能になります。

**複数具体値変数の代入順序例**（Ansible-Legacyと同様）: パラメータシート項目1〜4の値value1〜4を、`VAR_substitutionA`に順序30/10/20、`VAR_substitutionB`に順序2/4/1/3で紐付けると、ホスト変数ファイルには`VAR_substitutionA: [value2, value3, value1]`、`VAR_substitutionB: [value3, value1, value4, value2]`のように昇順で出力されます（代入順序が連続していなくても詰めて処理される）。

**多段変数の出力例**: `VAR_output`の`[0].name`と`[0].user.root[0].dev[0].dev_user`にのみ具体値（value1, value2）を紐付けると、ホスト変数ファイルには`VAR_output: [{name: value1, user: {root: [{dev: [{dev_user: value2}]}]}}]`のように、具体値を登録したメンバー変数のみが出力されます。

**ファイル/テンプレート埋込変数の利用例**: ファイル管理の`CPF_test`、テンプレート管理の`TPF_sample`をパラメータシート項目値として登録し、代入値自動登録設定でRole内変数（例: `VAR_filetest`, `VAR_temptest`）に紐付けることで、作業状態確認の代入値確認で具体値`'{{ CPF_test }}'` `'{{ TPF_sample }}'`が反映されていることを確認できます。

## 作業実行 / 作業状態確認 / 作業管理 / 作業対象ホスト / 代入値管理

Ansible-Legacyと同様の操作です。**作業実行**の実行種別: 作業実行（構築作業を実行）、ドライラン（`--check`相当）、パラメータ確認（代入値自動登録設定の情報を代入値管理・作業対象ホストに反映して確認）。予約日時は未来日時のみ指定可。

**作業状態確認**: ステータス・実行ログ・エラーログを表示。AAC実行時は機器一覧のユーザ・パスワード・ssh秘密鍵ファイル・パスフレーズ・接続タイプ・インスタンスグループでグループ化した単位、さらにジョブスライス数でも分割されログがTab表示されます（`exec.log`＝全ログ、`exec_<グループ番号>_<通番>`＝分割ログ）。作業対象ホスト確認・代入値確認・緊急停止／予約取消ボタン、ログ検索、投入データ・結果データのダウンロード、収集状況（収集済み／収集済み（通知あり）／対象外／収集エラー）が確認できます。

**作業管理**: 作業No.、実行種別、ステータス、緊急停止フラグ、実行エンジン、呼出元Conductor、実行ユーザ、登録日時、Movement詳細、オペレーション、投入データ・結果データ、作業状況、収集状況、Conductorインスタンス番号を一覧・フィルタ表示。

**作業対象ホスト**: 項番、作業No、オペレーション、Movement名、ホスト名、備考を閲覧。

**代入値管理**: 項番、作業No、オペレーション、Movement名、ホスト名、Movement名:変数名、Movement名:変数名:メンバー変数、具体値（Sensitive設定True時は暗号化されansible-vault経由、False時は具体値表示／ファイル名）、代入順序、備考を閲覧。

## ロールパッケージの記述

基本書式はAnsible公式マニュアルのベストプラクティスを参照してください。zipに含めるディレクトリとITAでの扱い:

| ディレクトリ/ファイル | 必要性 | ITAでの取り扱い |
|---|---|---|
| site.yml（マスターPlaybook） | 任意 | ITAで作成されるため存在すれば上書き |
| hosts | 任意 | ITAで作成されるため存在すれば上書き |
| group_vars | 任意 | ITAでは扱わないため存在すれば削除 |
| host_vars | 任意 | ITAで作成されるため存在すれば上書き |
| ITA readme | 任意 | ロール毎に定義。UTF-8 BOMなしで作成 |
| roles | 必須 | ないとアップロードエラー |
| roles/[role名] | 必須 | tasksディレクトリを含むディレクトリをroleとして扱う。階層が深くても可 |
| roles/[role名]/tasks | 必須 | main.ymlが必須（UTF-8 BOMなし）。他ファイルも配置可 |
| roles/[role名]/handlers, templates, files, vars, defaults, meta | 任意 | 各ファイルはUTF-8 BOMなしで作成（内容・有無はITAは関知しない） |

**ロール名がディレクトリ階層の場合**: tasksディレクトリがある階層をロールとして認識します。親ディレクトリにtasksがある場合、その配下の子ディレクトリにtasksがあっても子はロールとして扱いません（最上位のtasksのみが有効）。

**マスターPlaybook**はヘッダーセクション（Movement一覧のヘッダーセクションで変更可、デフォルトは前述の通り）とrolesセクション（Movement-ロール紐付のインクルード順序に従い各roleを実行）で構成されます。

## ITA readmeの記述

Playbook中に変数を直接定義したくない場合や、defaults変数定義ファイルに変数が未定義の場合、ITA readmeファイルに変数定義を記述することで代入値管理機能から具体値を指定できます。命名規則は`ita_readme_[ロール名].yml`（ロール名に`/`を含む場合は`%`に置換、例: `mysql/install`→`ita_readme_mysql%install.yml`）。フォーマットはYAML、UTF-8 BOMなし。

変数採用ルール: defaultsのみ定義→defaults側の構造を適用、ITA readmeのみ定義→ITA readme側を適用、両方定義→ITA readme側が優先。ITA readmeは作業実行時にロールパッケージから切り離され、記載した変数・具体値はansibleには渡りません（ITAへ変数名・型を伝えるための機能で、具体値の定義用ではない）。

**活用例**: ①外部（Galaxy等）取得のRoleを編集せず、「roles」ディレクトリ外にita_readmeを置いてパラメータを与えられる。②ita_readmeは変数名・型をITAに伝える機能であり具体値定義用ではない。③`defaults/main.yml`の変数・デフォルト値はhost_varsで上書きされない限り有効。④host_varsファイルはITAのパラメータシートから実行毎に自動生成される。⑤`defaults/main.yml`に変更を加えたくない場合、ita_readmeに追加変数を定義できる救済策として使える（重複時はita_readme優先）。⑥⑦length評価やdefined評価による条件分岐に、ita_readmeで定義した変数への具体値の有無を利用できる。

## 付録: Ansible実行時の投入データ・結果データ

投入データはZIP形式で作業状態確認からダウンロード可能です（機器一覧のパスワードやSensitive設定Trueの変数はansible-vaultで暗号化）。主な対応関係: ロールパッケージ→`/roles`、テンプレート/ファイル素材→`/template_files`/`/copy_files`、代入値管理の具体値（ファイル）→`/upload_files`、各種変数・機器情報→`/host_vars`、ssh/winrm鍵ファイル→`/ssh_key_files`/`/winrm_key_files`、サーバ証明書→`/winrm_ca_files`、オプションパラメータ→`/AnsibleExecOption.txt`（Core/AAC）または`/env/cmdline`（Agent）、機器一覧の接続情報→`/hosts`（Core/AAC）または`/inventory/hosts`（Agent）、ロール名・インクルード順序→`/site.yml`、実行環境関連ファイル（Agent利用時のみ）→`builder_executable_files/`、`runner_executable_files/`。

結果データの主なファイル: `result.txt`（Core限定）、`error.log`/`exec.log.org`/`exec.log`（全エンジン共通）、`exec_<作業番号>_<グループ番号>`（AAC限定の分割ログ）、`forced.txt`（緊急停止記録、Core/Agent）、`user_files`（`__workflowdir__`出力先、全エンジン共通）、`child_exec.log`/`child_error.log`（ansible-builder実行ログ、Agent限定）。
